# 直播监控：已知限制

记录直播监控（`backend/monitor/`）和开播/下播通知（`backend/notify/`）目前**做不到**或**有条件**的地方。接工作流前先看这里。

## 事件可能漏掉

### 停机期间整场直播会漏掉
服务停机期间，如果某人**开播又下播**，这一整场不会有任何通知，重启后也不会补发。

- 只有停机时间比一整场直播还长才会发生，比如长时间维护、宕机，或部署时碰上一场很短的直播。
- 停机期间只发生一半的情况**不会**漏掉，因为状态存在 `data/notify_state.json`：
  - 停机前在播、停机时下播：重启后补发下播。
  - 停机时开播、重启时还在播：重启后补发开播。

**以后要处理的话**（2026-11-10 讨论后暂不做）：
- 做法是重启时回头查停机期间有没有直播过。
  - YouTube：用频道的公开 RSS（`youtube.com/feeds/videos.xml?channel_id=...`）找停机期间的新影片，再从影片页的 `liveBroadcastDetails` 读开始和结束时间。不用 API key。RSS 有几分钟到十几分钟的延迟（未实测），要在重启后 30 分钟内多查几次。
  - Twitch：要用官方 Helix API（免费，要注册开发者应用拿 Client ID/Secret）查过去的直播（`/videos?type=archive`）。主播关掉直播存档就查不到。
- 补发一定是事后的，晚多久取决于停了多久，没有上限。补发的事件应加上 `backfill` 标记，只适合下载存档、做切片这类不赶时间的工作流。

### Webhook 失效时通知直接丢弃
Discord 返回 4xx（Webhook 被删、网址错误）视为永久失败：只记 error 日志，不重试，那条通知就丢了。5xx、网络错误会重试最多 5 次，间隔逐渐拉长，最长 60 秒，5 次都失败也会丢弃。

### 关机时没发完的通知
服务关闭时最多等 10 秒把排队中的通知发完，超过就丢弃。

## 事件会延迟

| 事件 | 延迟 | 原因 |
| --- | --- | --- |
| 开播 | 0 ～ 1 分钟 | 每 60 秒检测一次（`monitor.interval`） |
| 下播 | 约 2 ～ 3 分钟 | 最多 1 分钟发现，再等 2 分钟确认不是断线（`notify.offline_grace`） |
| 检测连续失败期间 | 失败多久就延迟多久 | 网络断线、YouTube 人机验证页都算检测失败，不会改变状态，恢复后才发 |

## 行为上的约定

- **服务启动时已经在播的不发开播**，因为没有保存过的状态，不知道是不是新开的。可用 `notify.on_startup: true` 改成要发。之后的下播照常发。
- **同一时间只能跑一个监控进程**：网页服务和命令行二选一，也不要本地和服务器同时跑。它们会共用状态文件，而且会重复发通知。
- **开播和下播靠 `stream_id` 配对**：YouTube 是影片 ID，Twitch 是开播时间。同一场的 ID 以开播时为准，之后不变。
  - 开播时平台没给 ID 的话（很少见），这场直播结束前，两次检测之间换了新一场也认不出来，要等下播后才算新的一场。
- **直播结束后 YouTube 马上显示下一场预约待机，也算下播。**

## 平台相关

- **YouTube、Twitch 和 TwitCasting 都是读公开网页，不是官方 API。** 平台改版可能让检测失效。失效时会显示「检测失败」，不会误判成下播，但在修好之前收不到通知。改版后跑 `uv run pytest -m network -s` 可以检查。
- **YouTube 没有观看人数**：页面里没有，要用 Data API。
- **Twitch 的观看人数可能不是实时的**：取自页面描述，测试时间隔约 10 分钟的两次都是同一个数字，可能被 Twitch 缓存了。
- **TwitCasting 支持开播 / 下播通知**：每次检测读一次频道页 `twitcasting.tv/<ID>`，看 `<body data-is-onlive>`。卡片和通知有标题、封面、头像和开播时间。
  - 频道可以填 ID、`@ID` 或 `twitcasting.tv/<ID>` 网址；ID 可以带冒号（`c:name`、`g:123`）。
  - 标题是这一场自己的标题：TwitCasting 在 `og:title` 后面加的「 / 频道标题」会去掉。这一场没有自己的标题时，显示频道标题。
  - `stream_id` 是 TwitCasting 的 movie ID；直播网址一律是频道网址。断线重连会开新的一场，movie ID 也会变。
  - 没有观看人数：页面里没有，另一个接口给的人数一直是 0。
  - 没有「预约待机」，只有在播和没在播。
  - ID 打错时 TwitCasting 回的是首页（HTTP 200），会显示「检测失败」，不会当成下播。
  - 开播又下播都在两次检测之间（不到 1 分钟）的直播看不到。
  - 还不会自动下载 TwitCasting 的回放。
- **不支持 X（Twitter）语音直播 Spaces**：公开网页拿不到；官方 API 自 2026 年 2 月起按用量收费；用登录状态调内部接口会违反 X 条款。目前只能靠 X App 的 🔔 通知。
